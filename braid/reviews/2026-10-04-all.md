# Review: braid v1 release candidate (whole repo)

Written by `/braid:xreview all` (adversarial). Paste this into a different model or a fresh session, opened at the repo root of a braid checkout at commit `72c059d` or later. Read-only: change nothing; report.

## 1. Role

You are a senior SRE and staff software engineer. Your job is to break this: find what fails, is missing, or contradicts its own docs, decisions, or principles before it is published as a public plugin.

## 2. Intent

braid is a plugin for **Claude Code, Codex and ZCode**: an always-on core of clean-code rules (YAGNI > KISS > DRY, derived from ponytail) injected by a session hook, plus skills for grilling plans, spec-driven changes, repo maps, AGENTS.md standards, handoffs, and reviews. Read these first:

- `README.md`: what it claims to be and do, install steps, benchmark claims
- `braid/routes/v1.md`: every v1 decision, one line each
- `braid/adr/0001` through `0010`: the significant decisions and why
- `braid/changes/ship-v1/`: what is left before release
- `skills/braid/core.md`: the always-on rules (the principles you also review against)
- `UPSTREAM.md`: where every skill came from (vendored, derived, clean-room) and its license

## 3. Scope

Everything braid wrote, `git ls-files` minus the exclusions below:

- **Hook and harness:** `hooks/braid.cjs`, `hooks/hooks.json`, the three manifests (`.claude-plugin/`, `.codex-plugin/`, `.zcode-plugin/`), `.agents/plugins/marketplace.json`
- **braid's own skills:** `skills/{braid,review,audit,debt,map,spec,wayfind,handoff,xreview,design,standards}/`
- **braid's edits to vendored skills only:** `git diff d5c011f HEAD -- skills/grilling skills/grill-me skills/grill-with-docs skills/domain-modeling skills/adhd skills/humanizer skills/security-audit skills/systematic-debugging` (d5c011f is the verbatim upstream copy)
- **Tooling:** `scripts/check.cjs`, `.github/workflows/check.yml`, `bench/ab.cjs`, `bench/tasks/`
- **Docs:** `README.md`, `TESTING.md`, `CHANGELOG.md`, `UPSTREAM.md`, `braid/`

Out of scope: vendored upstream text itself (only braid's diff on it), and the data in `bench/results/` (but do check the README's numbers against it).

You may run, and should: `node scripts/check.cjs` and `node bench/ab.cjs --fake` (no tokens, no network beyond a git clone of ponytail; they clean up after themselves). Node ≥ 18.

## 4. Principles

Judge against `skills/braid/core.md`, its Rules and the YAGNI > KISS > DRY order with the rule of three. Flag **over-building** (abstraction, config, files, or prose that isn't needed) and **under-building** (a missing guard at a trust boundary, missing error handling that loses data, a claim with no check behind it) alike. braid's own skill files are capped at 8 KB each, and always-on context at ~2.5k tokens.

## 5. Check

- **Correctness of the hook** across Claude Code, Codex and ZCode: event names, the JSON output shape each accepts, `${CLAUDE_PLUGIN_ROOT}` expansion, Windows (stdin that never closes, paths, `.cjs` under a `"type": "module"` parent), the per-session state file, pointer lines for `braid/changes` and `openspec/changes`, the level/drift/adhd tracker, and what happens when state, git, or files are missing or malformed.
- **Manifests and install:** would each harness actually load the plugin, its skills, and its hooks as the README says? Is anything referenced that doesn't exist, or present that no harness reads?
- **Skill instructions:** contradictions between skills, or between a skill and `core.md`; paths that don't match (`braid/`, `openspec/`, `AGENTS.md`); a skill calling another that is user-invoked only; frontmatter the harnesses reject; Codex `agents/openai.yaml` policies; descriptions over budget.
- **Completeness against `ship-v1/tasks.md`** and the decisions in `braid/routes/v1.md`: is anything decided but not built, or built but not decided?
- **Licensing and attribution:** every vendored folder keeps its upstream LICENSE; nothing Apache-2.0 is copied; `UPSTREAM.md` SHAs and paths are real; README credits are accurate.
- **Claims vs evidence:** README benchmark table vs `bench/results/`; TESTING.md commands actually work; CHANGELOG matches what exists.
- **Security and privacy:** the hook runs `git` with values read from repo files; the benchmark spawns agents with auto-approved edits; anything that executes untrusted input, leaks local paths, user or host names, or writes outside its own folders.
- **Verification actually ran:** what `scripts/check.cjs` claims to test vs what it really asserts; gaps where a regression would pass CI.
- **Ops:** CI on Windows and Ubuntu with Node 18, release and versioning (`CHANGELOG.md`, manifest versions kept equal by the check), what a user sees when Node is missing.

## 6. Don't flag

- Style and wording preferences.
- Anything an ADR in `braid/adr/` already decided (one plugin; vendoring verbatim; CLI-free specs in `braid/`; state on disk without enforcement hooks; Node `.cjs` stdlib hook; the token budget; clean-room skills; AGENTS.md owning commands; following the project's spec framework). Flag only if the implementation contradicts the ADR.
- Speculative "what if later" features. YAGNI applies to reviews too.
- Known, recorded limits: ZCode hooks and marketplace path are unverified until the release install check; a spelled-out algorithm makes Claude skip reuse (recorded in the v1 route and README).
- A `braid(<pillar>):` corner-cut comment whose upgrade trigger hasn't fired.
- Vendored upstream text outside braid's diff.

## 7. Method

1. **Find.** List candidate findings, each with `file:line` and evidence only. No fixes yet.
2. **Refute.** Try to disprove each candidate against the code. Run `node scripts/check.cjs`, `node bench/ab.cjs --fake`, the hook by hand (`echo '{"session_id":"x","source":"startup","cwd":"."}' | node hooks/braid.cjs session`), or a small reproduction wherever possible. Keep survivors, labelled **CONFIRMED** (shown by running something) or **PLAUSIBLE** (reasoned only). Drop the rest.
3. **Fix.** For survivors only, the smallest fix, in braid's own principles.

## 8. Output

Findings ranked by severity:

`SEVERITY CONFIRMED|PLAUSIBLE file:line: problem. Evidence. Smallest fix.`

Severity: BLOCKER (must fix before publishing), MAJOR, MINOR. End with a section **What I could not verify** (for example: anything needing a real Claude Code, Codex, or ZCode install).
