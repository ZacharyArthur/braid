## 2. Intent

braid is a clean-code plugin for Claude Code, Codex and ZCode: an always-on core (YAGNI > KISS > DRY) injected by a Node session hook, plus workflow skills. This change adds **mods**: Claude Code-only plugins of TypeScript hooks that run inside Claude Code and can draw in its interface. Mods ship as separate plugins in braid's own marketplace, never inside the `braid` plugin, so Codex and ZCode behavior is unchanged.

The first mod, `braid-context`, draws one line above the prompt, meant to stand in for a status line (including in the Desktop app, which has none):

- **context** used against the window;
- the prompt **cache** countdown to going cold, with its TTL (5m or 1h), "live" while a turn runs (each request refreshes the cache), dimmed "cold" once expired;
- the last turn's cache **hit** rate;
- **spend**: percent of the 5-hour usage window on a subscription (at 100%, "5h limit until <local reset time>" instead), the session's cost in dollars on API or Bedrock. A `five_hour` or `seven_day` window marks a subscription, so between 5-hour windows the slot stays empty rather than showing dollars; a gateway's `spend_limit` counts as API;
- **braid**'s level and the active change's task progress, when braid is installed and on.

Colours: the cache countdown turns red under 1 minute, and on a 1h TTL yellow under 5 minutes first (a 5m cache would be yellow from its first second); context and the 5-hour window share one fill scale, yellow from 75% and red from 90%; the hit rate turns yellow under 80% and red under 50%, except on a conversation's first response (it always writes the whole cache); context, the window and the hit rate are coloured by the rounded figure as shown; the limit line is red. The 5-hour figure is the last response's, so once its reset time passes the band drops it (the slot stays empty, no dollars) and redraws at that moment even while idle. The countdown runs from when the turn's last main-thread request was sent (a `turn.step` hook records the time), not from the turn's end, and is coloured by the seconds shown. A new conversation (startup, `/clear`, resume, compact) clears the cache figures until its first response, and spend waits for that response too: only a response tells a subscription from API, so a resumed subscription never flashes its history's dollars. The band is always one line, cut at the edge with an ellipsis (`<Text wrap="truncate-end">` around the parts). From 120 columns up, context fill, cache time left and the 5-hour window also get 8-cell bars of `█`/`░`; below that the band is text only. Example at 120 columns:

```text
ctx ██░░░░░░ 312k/1M 31% · cache ███████░ 52:10 (1h) · hit 97% · 5h ██░░░░░░ 23% · braid full · add-mods 15/18
```

## 2a. Round 1 findings and what became of them

Fixed, each with a regression test unless noted:

- TTL parsing trusted any `"cache_creation":{…}` text and threw on a malformed fragment, which skipped the whole `turn.complete` hook. Now whole records only, assistant and not sidechain; lines that don't parse are skipped.
- Dollars shown on a subscription whose `five_hour` window was absent (after a reset). Now `isSubscription` (`five_hour` or `seven_day`) gates dollars and the 1h fallback.
- The countdown kept running from the previous turn during a long turn, reaching "cold" while the cache was warm. Now "live" while `isWorking`. Decision: this over a per-request `turn.step` hook, which Codex's "the last response had no cache tokens" case would also need; that case was judged too unlikely to pay for.
- A tick that fired late past expiry never drew "cold". Now the tick remembers which cache write it drew cold and redraws once on the transition (no test: the mock clock fires every tick).
- Any JSON value in braid's `mode` reached `<Text>`. Now only `lite`, `full` or `ultra`, else `full`; `off` hides braid.
- braid's level was read before braid's own settings hook (beneath mods, per the typings' `ClassicEventOf`) recorded a switch. Now it is read after `next(e)`.
- `1000k/1M` at 999,600 tokens; a yellow `90%` at 89.6%; a `projects` folder above the config folder broke the state path (now cut from the end); README's braid clause.
- A 5m TTL was yellow from its first second (decision: no yellow stage on 5m). The band wrapped between 100 and 109 columns and overflowed 80 with an active change (decision: one line, truncate-end, bars from 120).

Dismissed, with reasons; re-raise only with new evidence:

- Ticker lost on hot reload: a reload runs `register` and `session.start` again.
- A subagent's `classic.UserPromptSubmit` overwriting the session: every source the typings list is main-loop.
- A 1h cache expiring at write time + 1h despite reads: Anthropic refreshes the TTL on each cache hit.
- "Before the first response, no spend" on `--resume`: decided in round 1 to show resumed dollars at once; reversed in round 3 (see 2c).

## 2b. Round 2 findings and what became of them

Fixed, each with a regression test:

- The 5-hour figure outlived its reset while idle ("5h limit until 7:00 PM" past 7:00), because `rateLimits` holds what the last response reported and nothing redrew. Now `fiveHour()` drops a window whose `resetsAt` has passed, and the once-a-second tick redraws when a deadline passes since its last tick: the cache going cold or the 5-hour reset (this replaces round 1's "drawn cold" marker). The test fails with the reset deadline removed.
- A `session.measure` hook now invalidates the band whenever the engine reports context, windows or cost moved (no test: one line, no branch).
- The hit rate was coloured from the raw fraction: `hit 80%` in yellow at 79.6%. Now coloured by the rounded figure.
- The spec's "API or Bedrock spend" said "no usage window", but a gateway's `spend_limit` is one; now "no 5-hour or 7-day window". New scenario "5-hour window resets".
- The 999,600-token boundary had no direct test; now it does. Task 1.9 now names its one untested fix (the late tick).

Decided: bars keep `█`/`░`. `█` is East Asian Ambiguous width; the code comment now says so instead of claiming single width everywhere (decision: the look over `▰▱` or ASCII, since the risk is a rare terminal setting Claude Code's own interface shares).

Dismissed, with reasons; re-raise only with new evidence:

- "The reset-time test is tautological": it computes the expected time in local time, so a mod showing UTC fails on any machine not set to UTC.
- "Past 4 MiB the TTL goes stale": the recorded corner cut. There is still no way around it: `$.fs.read` has no range or tail option, `$.session.messages()` carries no usage, and `$.session.usage()` has no prompt cache.

## 2c. Round 3 findings and what became of them

Fixed, each with a test:

- The countdown started at the turn's end, so the time spent writing the final answer counted as cache life (on a 5m TTL, up to about a minute shown after the cache went cold). Now a main-loop `turn.step` hook records when each request is sent and `turn.complete` uses the last one as `at`; after a reload, before any step, the turn's end stands in. Decision: this timestamp over recording the gap in the spec.
- A resumed subscription showed dollars until its first response (`rateLimits` is empty until a response; the status line docs say the same of `rate_limits`). Now spend waits for the conversation's first response, for everyone. Decision: reverses round 1's "resumed dollars at once"; API users see them one response later. The spec's "Before the first response" now covers start, resume and clear.
- The countdown's colour was judged on raw milliseconds but the figure rounds up, so `1:00` showed red for a tick. Now coloured by the seconds shown.
- The tick read the cache atom with a raw `$.state.get` while everything else uses `read($, cache)`. Now `read`.
- `/compact` (and fork) also fire `classic.SessionStart` and clear the cache figures; the comment and task 1.8 now say "compact".

Also in this round: README's status line said "v1 release candidate" with a link to an archived change; braid is released and in use, so it now says so and points to CHANGELOG.md and the ADRs. The "live" test got the 20 s timeout the other long-clock tests have: it fast-forwards an hour of one-second ticks and timed out at 5 s on a busy machine.
