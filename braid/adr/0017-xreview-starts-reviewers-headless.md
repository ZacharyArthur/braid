# xreview starts reviewers as headless programs, named, auto-approved, in the one working tree

`--run` used to hand the prompt to a subagent of the author's own harness, the same model family a cross-review exists to avoid, so most review sessions were opened by hand only to paste a prompt. A session manager that drives agent terminals was weighed and rejected: it brings a daemon, its own worktrees and support for only some programs, for a job that is one prompt file in and one result file out. All four reviewer programs (`claude`, `codex`, `pi`, `vibe`) have a non-interactive mode, a model flag and a way to run without approval prompts, so `skills/xreview/run.cjs` is a table of four command lines and a `spawn`, the same in every harness with a shell; a fifth name, `glm`, is Codex's program again on the user's own `zai` profile, so GPT and GLM review side by side behind the same sandbox. Reviewers are always named (the list after `--run`, else a `Reviewers:` line in AGENTS.md's Workflow section, else a question): a default would spend several subscriptions' quota on a flag that used to start one subagent, and `subagent` is one more name, alone, instead of a fallback. Nothing a shell could read as more than a name reaches a command line: a model is limited to ASCII letters, digits and `._/:-` and may not start with `-`, which a program would read as a flag, a review folder's name to ASCII letters, digits and `._-`, both paths go relative to the working tree, and the hand-off line goes on stdin. The programs run without approval prompts in the shared checkout, each in its automatic approval mode where it has one (Claude Code's auto mode, Codex's approve-for-me, Vibe's smart-approve; Pi has none), Codex inside its workspace sandbox and the others with the user's rights: a read-only reviewer can't run a test or write its file, and a worktree doesn't hold the uncommitted changes the default scope includes. That is new exposure, so xreview says it before every fan-out, asks first on another author's commits or a secret-named file, and afterwards names what the programs left behind, as a check and not a boundary. `--offline` stays an instruction to every reviewer: enforcing it only where a sandbox exists would make it mean a different roster on each machine. Revisit worktrees and an enforced offline mode if the runner is later used to hand off implementation.
