# Standards writes explorer agents on a yes

`/braid:standards` writes documentation only, but an AGENTS.md line that names a fast model routes only while the main agent remembers to pass that model on every spawn (Claude Code, Codex), or not at all in ZCode (built-ins change only in Settings), and all three harnesses now run subagents on the main model unless told otherwise. So when a project opts into braid's delegation policy, standards may also write one read-only explorer agent per harness the user picks, each after its own yes: Claude Code's project `Explore` and Codex's project `explorer`, which replace the built-ins by name, and ZCode's `braid-explore` (ZCode refuses built-in names) in the project's `.zcode/agents/`, flagged as possibly not loading because ZCode documents only user-level agents. Declined or not loaded, the same file goes in `~/.zcode/agents/`: braid's only write outside a project, so its offer says it affects every project and shows an existing file before replacing it; declined too, standards prints the Settings step instead. Nothing else in standards becomes config: hooks, branch protection and host settings stay out, and mid-tier agents aren't written (Claude Code passes `model` per spawn). Delegation stays opt-in, recommended off, because a subagent moves reading cost rather than removing it and adds a fixed cost per spawn.
