# Retro routes to vendor tools instead of rebuilding them

Each harness already ships usage, cost, config, permission and memory tools (Claude Code's `/insights`, `/usage`, `fewer-permission-prompts`, `update-config`, `consolidate-memory`; Codex's `/status`, `/usage`, `/debug-config`; ZCode's `zcode-guide` diagnosing skills), and the vendors keep them current. So `/braid:retro` builds only what none of them does: it finds tool failures that recur across sessions in every harness's transcripts and turns them into rules for the file all three harnesses read, AGENTS.md, written only after a yes and never into a harness's memory. Everything else is a router at the end of the run: one row per kind of finding, naming the vendor tool for the harness the user is in, a skill run after a yes, a built-in command named for the user to type (no harness lets the model run one), and a dated table checked against the skill list at run time rather than by tooling. The extractor reads ZCode's SQLite store through `node:sqlite` when the running Node has it (22.13 or later) and says it skipped ZCode otherwise, so braid keeps its Node 18 floor and its no-dependency rule. Amended 2026-10-22 (add-skill-evals): Pi's JSONL sessions are read as well, its user-level file is `<agent folder>/AGENTS.md`, and its tools join the router.
