# Mods are Claude Code-only plugins listed in braid's own marketplace

Claude Code mods (TypeScript hooks modules run by its engine) have no Codex or ZCode equivalent, so none ships inside the `braid` plugin: that would break identical behavior across the three harnesses (ADR 0002) and pull a second toolchain into its gate. Each mod is its own plugin under `mods/<name>/`, listed in `.claude-plugin/marketplace.json` with a "Claude Code only" description, so installing and switching one off is `/plugin`'s job and braid builds no toggle. Codex reads only `.agents/plugins/marketplace.json` when it exists (tested 2026-10-08), so it never sees mods; ZCode reads `.claude-plugin/marketplace.json` and lists them, which the label covers, but it only runs a plugin's command hooks. braid's own copy carries `mods/` unloaded, a few KB. We chose this over `userConfig` toggles inside braid (Claude-only behavior in a three-harness plugin), a second marketplace file (Claude users would hand-edit `extraKnownMarketplaces`, as `marketplace add` takes no path) and a separate repo (a second thing to release). This refines ADR 0002 rather than reversing it: its no-toggleable-bundles reasoning covers skills, not mods. Move mods to their own repo once they need their own release cadence or CI, or ZCode users start installing them by mistake.
