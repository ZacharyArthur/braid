# One plugin, one skills folder, three thin manifests

braid ships as a single plugin for Claude Code, Codex and ZCode: one `skills/` folder, `.claude-plugin/`, `.codex-plugin/` and `.zcode-plugin/` manifests, and one Claude-format `hooks/hooks.json`. We chose one plugin over a marketplace of toggleable bundles because user-only skills cost no always-on tokens anyway. User-only is expressed three ways because each harness differs: `disable-model-invocation` (Claude Code), `agents/openai.yaml` policy (Codex), and a description suffix (ZCode has no flag; its Settings can't switch off plugin skills one at a time either, so there the suffix is only a hint and user-only skills can auto-load, found 2026-10-04). `scripts/check.cjs` enforces all three. Amended 2026-10-20 (add-pi-harness): Pi is a fourth harness. It runs no `hooks.json`, so a thin extension, `extensions/braid.js`, runs `hooks/braid.cjs` as a child process on Pi's session and input events and puts its output in a system prompt section. The hook stays the only logic, its state in `braid/` inside Pi's agent folder (passed as `PLUGIN_DATA`), and Pi finds the extension and `skills/` by its package conventions, with no fourth manifest. Pi honors `disable-model-invocation`, so user-only needs no fourth mark. Pi has no subagent event, so, as in ZCode, subagents there get no core.
