# One plugin, one skills folder, thin manifests

braid ships as a single plugin for Claude Code, Codex and ZCode: one `skills/` folder, `.claude-plugin/`, `.codex-plugin/` and `.zcode-plugin/` manifests, and one Claude-format `hooks/hooks.json`. We chose one plugin over a marketplace of toggleable bundles because user-only skills cost no always-on tokens anyway. User-only is expressed three ways because each harness differs: `disable-model-invocation` (Claude Code), `agents/openai.yaml` policy (Codex), and a description suffix (ZCode has no flag; its Settings can't switch off plugin skills one at a time either, so there the suffix is only a hint and user-only skills can auto-load, found 2026-10-04). `scripts/check.cjs` enforces all three. Amended 2026-10-20 (add-pi-harness): Pi is a fourth harness. It runs no `hooks.json`, so a thin extension, `extensions/braid.js`, runs `hooks/braid.cjs` as a child process on Pi's session and input events and puts its output in a system prompt section. The hook stays the only logic, its state in `braid/` inside Pi's agent folder (passed as `PLUGIN_DATA`), and Pi finds the extension and `skills/` by its package conventions, with no fourth manifest. Pi honors `disable-model-invocation`, so user-only needs no fourth mark. Pi has no subagent event, so, as in ZCode, subagents there get no core. Amended 2026-11-15 (add-vibe-harness): Mistral Vibe is a fifth harness, with no adapter. Vibe runs command hooks itself, from a native Agent Plugins manifest: a root `plugin.json`, the fourth manifest, on the shared version and with no description (Vibe would inject it every session). That manifest outranks the Claude Code and Codex ones Vibe would otherwise reject as ambiguous, and `ai.mistral.vibe/hooks.toml` runs `hooks/braid.cjs` on `session_start` and `pre_agent`. The hook tells Vibe's payload by its event names, answers in Vibe's key, and keeps state in Vibe's per-session `PLUGIN_DATA` alone. Vibe honors `disable-model-invocation`, so user-only needs no new mark. The gaps are stated, not emulated: the core rides the first user message rather than the system prompt, is not re-injected after compaction (as in ZCode), and never reaches subagents (as in ZCode and Pi).
