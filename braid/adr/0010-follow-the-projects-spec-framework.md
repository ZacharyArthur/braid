# Follow the project's spec framework; OpenSpec gets first-class support

braid's spec workflow yields to whatever the project already uses. AGENTS.md's Workflow section declares it (`Specs: <framework> (<dir>)`); without that line `spec` detects it. With OpenSpec, every `spec` verb reads and writes `openspec/specs` and `openspec/changes` in OpenSpec's formats (including RENAMED deltas), follows `openspec/config.yaml`, and uses the `openspec` CLI when installed; only specs and changes move, while ADRs, glossary, map, routes and handoff stay in `braid/`. The session hook follows `openspec/changes` too. Any other framework (Spec Kit, Kiro, BMAD, ...) is asked about once, followed by default, and recorded in AGENTS.md. An explicit request for braid's workflow overrides all of it. We chose this over forcing `braid/` because a second, competing spec tree in someone's repo would be worse than either alone.
