# skill writes its own eval path instead of vendoring a skill creator

`skill`'s heavy path (evals against a baseline, trigger tuning) used to hand off to Anthropic's `skill-creator` when installed, and it rarely is outside Claude's desktop app and web: Codex ships a creator without evals, ZCode and Pi ship none. Vendoring Anthropic's (Apache-2.0) was weighed and rejected: ~250 KB of skill, Python scripts and an HTML viewer, its trigger tuning runs only through `claude -p` so in other harnesses it would measure Claude rather than that harness, and its nested `SKILL.md` would need renaming so recursive skill discovery (Pi's, maybe Codex's) doesn't load it as a second skill. So braid writes `skills/skill/evals.md`, clean-room from Anthropic's skill-creator and best-practices guide, Codex's skill-creator and agentskills.io's guides: fresh runs with and without the skill, assertions graded with quoted evidence, the user's review, and opt-in trigger tuning with a held-out set, with a fresh-run recipe per harness and no scripts. An installed creator the user prefers still takes the work, and `skill`'s checks run on its output. Revisit if trigger detection in Codex's and Pi's headless output is confirmed and a small `.cjs` loop would save real effort.
